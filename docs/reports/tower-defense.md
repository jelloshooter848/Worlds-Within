# The tower-defense kit: lessons report

Engine 0.12 ([ROADMAP, 0.12 Tower-defense kit](../ROADMAP.md#012-tower-defense-kit-the-platform-test-done))
adds a new genre, `kits/towerdefense`, a standalone sample, `games/samples/tower-defense/`, and a
small tower-defense preparation phase in the mini siege: towers placed on the real walls with real
gold, fighting a wave of the real raiders, with the losses written back to the world.

## Purpose

This is **the platform test**: a new mode added to an existing game with **no change to
`engine/sim`**. Every change the new mode does need (in `engine/core`, `engine/tools`, a backend, the
mission contract, another kit or the mini siege's glue) is written down here as it is found, as a
lesson for the mission API before that API is fixed at 1.0. A change `engine/sim` would need is
not made in 0.12 unless there is no other way, and then it is justified here and in the release
notes. The close-out records the empty `git diff` of `engine/sim` against the release's base
commit, `d6a102ab66f62c80e906ac979ece026dd781c415` (item 206).

The decisions this release is built against (items 197-206) are in
[BUILD-LOG.md, Engine 0.12, Decisions](../BUILD-LOG.md#decisions-3).

**No earlier gap is assigned to 0.12.** Neither the [stacking-test report](stacking-test.md) nor
the [mini-siege report](mini-siege.md) moves any gap to 0.12: every `G` and `M` gap is fixed or
moved to 0.13, 0.14 or 0.15, and the only "0.12" in `mini-siege.md` is its format's line listing
the releases a status may name. The close-out (T9) checked both again: still none, and neither
report was changed in 0.12.

**A lesson expected from the start:** a mission outcome's effects carry fixed amounts, so the gold
a round spent can only be written back as the amount the matching outcome declares (bucketed
outcomes), not the amount the round reports (item 201). If the build hits it, it gets a row here.

## Summary

Engine 0.12 is closed (T9). **The platform test passed: the `engine/sim` diff for the release is
empty.** On the close-out's tree, against the base commit `d6a102ab66f62c80e906ac979ece026dd781c415`:

```text
$ git diff --stat d6a102ab66f62c80e906ac979ece026dd781c415 -- engine/sim
(no output)
$ git log --oneline d6a102ab66f62c80e906ac979ece026dd781c415..HEAD -- engine/sim
(no output)
```

So no change needs a justification in the release notes. Outside `engine/sim`, the release changed
in the engine only the one line every new kit adds (`towerdefense` in `KIT_HOOKS`,
`engine/tools/kit-list.ts`, so `validate`, `mutants` and the generated references know the kit) and
the content kinds' list of error codes (`engine/core/content/CLAUDE.md`). No `engine/core` code, no
backend and no other kit changed: the mini game contract, `MissionHost`, `playMissionRound`, the
shell, `frameView` and `skinSet` from 0.7 to 0.11 were enough for a new genre, a standalone sample
and a new mode in an existing game.

**14 lessons**, `D1`-`D14`, every one with what, where and a status. None needed `engine/sim` and
none was fixed in 0.12 (decision 9: they are recorded for the mission API, not patched one game at
a time). Each is moved to a named release and listed in that release's section of
`docs/ROADMAP.md`:

- **12 to 0.15, the sample set's API review** (the last chance to change a kit or module API before
  it is written down as v1, with four samples to compare): D1, D2, D3, D4, D6, D7, D8, D9, D10,
  D12, D13 and D14 (found in the glue review below). D3 and D4 (effect amounts and losses taken from
  the round's report) would change how the sim's commit applies effects, so they are made there,
  with the other mission-contract changes, not in a release whose test is an empty sim diff.
- **2 to Engine 1.0, written down in the v1 docs as the API's rule, not changed:** D5 (walls lost
  are the report's reading of the round, not a kit rule) and D11 (two missions on one event exclude
  each other for the whole cost: the sim's frozen-event rule from 0.10).

**What the platform test showed.** A new genre is a kit with its own deterministic rules, content
kinds and frames, and joining it to a world is one more data-driven mini game and adapter
(`td-defence`, `towerdefenseMissionAdapter`) beside the topdown kit's `mission-room`: the mini
siege's glue only added both to the lists it already passed to `MissionHost`. What is awkward is
the mission API's expressiveness, not its shape: an outcome's effects are fixed per outcome (D3,
D4), the round reaches world entities only by the keys those effects name (D6) or by order (D10),
and `validate` cannot check params against the world (D7). The rest is page glue a second hosting
game copies (D2, D9, D12, D13, D14), which joins the mini siege's M6, M21 and M26 at 0.15.

## Format

Each lesson has one row, in the order found; ids are `D1`, `D2`, ... (D for defence) and are never
reused or renumbered (item 205), so they do not mix with task ids (`T1`, ...) or the stacking test's
`G` and the mini siege's `M` ids.

- **Id:** `D1`, `D2`, ...
- **What:** what the new mode needed, or what was awkward, in a sentence or two.
- **Where:** the file or module it was found in (and the one that should own it).
- **Sim:** whether `engine/sim` needed it (`no`, or `yes` with why it could not go elsewhere).
- **Status:** `fixed in 0.12 Tn (<commit>)`; or `moved to <release>` (0.13, 0.14, 0.15, 1.0, ...)
  with the reason and where it lands there. During the build a lesson's status was `lesson for the
1.0 mission API`; the close-out (T9) gave each one its release: `moved to 0.15` for a change the
  sample set's API review makes (or rejects) before v1, `moved to 1.0` for a rule written down in
  the v1 docs as it is. Each row also names the task and commit that found it.

**Engine 0.15:** **D1, D2, D12 and D13 are fixed** in T5 (`12d38ae`: taps as frame input, a
scene's tick rate, taps into hosted rounds, `screenAtCell` and `toClient`).

**Engine 0.15:** **D9 is fixed** in T6 (`685f09e`: the host names the hosted mini game on the
round's frame).

**Engine 0.15:** **D6, D7, D8 and D10 are fixed** in T7 (`6d891a1`: the world's key table handed
to the adapter, selectors checked against the world scenarios, `td-map` without waves, walls on
named cells).

**Engine 0.15:** **D3 and D4 are fixed** in T8 (`77700b6`: effect amounts and losses taken from the
round's report, checked against declared limits).

**Engine 0.15:** **D14 is fixed** in T10 (`b490bfc`: a round's key hint from the mini game's
controls or the mission file, written with the player's keys).

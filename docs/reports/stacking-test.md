# The stacking test: gap report

The stacking test ([ROADMAP, 0.7 The stacking test](../ROADMAP.md#07-the-stacking-test-done)) builds a
small original platformer, `games/platformer-test/`, on the engine as it is, and shows it through
both backends (2D sprites and 3D), with one level whose door pushes a top-down mini game over the
level. Its point is to find out what is missing: **every gap is written down here as it is found**,
whether it is fixed in Engine 0.7 or moved to a named later release.

A gap is anything that needed engine code changes, anything awkward, or anything the game had to do
that should have been the engine's (or a kit's) job. The rule of thumb is DESIGN.md's: if two games
could use it, it is engine; the game folder holds only content, skins and thin glue.

## Summary: what stacking showed

Engine 0.7 is closed (T9): **37 gaps**, every one with what, where and a status. **20 were fixed
in 0.7** (G1-G4, G6, G7, G11, G14, G15, G19, G21-G26, G29, G32, G34, G35) and **17 moved to a named
later release**: 0.10, the time and mission contract (G16, G20, G37); 0.11, the mini siege
(G13, G18, G27, G28, G30); 0.14, the creator tools (G5, G8, G9, G10, G12, G31); 0.15, the sample
set (G17, G33, G36). Each later release's section in `docs/ROADMAP.md` lists the gaps it took.
(Until Engine 0.10 this paragraph said 21 and 16; the lists were always 20 and 17.)

**Engine 0.10 is closed: G2, G16, G20 and G37 were fixed in 0.10.** G16 in T8 (`b0a2d1a`: params
checked by `validate`), G20 and G37 in T9 (`14953b2`: the round's last tick in the snapshot, the
hosted round in the game contract; `scene.ts` is gone from both games), and the rest of G2 in T10
(`b725997`: the `campaign` file; G2 was already counted fixed in 0.7). **Counts now: 23 fixed** (20
in 0.7, 3 more in 0.10) **and 14 open, each moved to a named release**: 0.11 (G13, G18, G27, G28,
G30), 0.14 (G5, G8, G9, G10, G12, G31) and 0.15 (G17, G33, G36).

**Engine 0.11 is closed: G13, G18, G19 (the rest), G27, G28 and G30 were fixed in 0.11.**
G18 fixed in T2 (`525d172`: a round's own input map, and a button held into the
round ignored until released), and the rest of G19 with it (a round's HUD can show
the host's values; G19 was already counted fixed in 0.7). G27 and G28 fixed in T3 (`4345818`:
the shell's `audio` option, and skin event keys with a field match such as `mini-game-end:pass`).
G13 and G30 fixed in T4 (`7eebb3d`: an optional `look` on a level's trigger entry, presented as
the tag `look:<id>`, and a skin's `byTag` looks). **Counts now: 28 fixed** (20 in 0.7, 3 more
in 0.10, 5 more in 0.11: G13, G18, G27, G28, G30; G19 was already counted in 0.7) **and 9 open,
each moved to a named release**: 0.14 (G5, G8, G9, G10, G12, G31) and 0.15 (G17, G33, G36). The
mini siege uses G19's host status and G28's result sounds in its skins; its own gaps are in
[its report](mini-siege.md).

- **Stacking works with the contracts as they were.** A platformer level hosted a top-down room
  through the engine's `MiniGameDef` with no change to the platformer kit (T5), and the round's
  result acted on the level headless, in 2D and in 3D, with the same state hashes on every
  backend. The engine's mini game contract, the kits' frames and skins carried a second kit
  without new arrows in the dependency table.
- **What was missing was glue, not rules.** Most gaps were code every game copied: the level
  flow (G1, G3), the browser boot, scene, frame stream and view (G21-G26), the content glue
  (G2, G4, G35), the skin per frame source and its framing (G14, G29, G32, G34). All moved into
  `engine/core`, the backends or the kits, and the lab and the demo use them too.
- **A second kit in one game is a content question first.** `uses` in `game.json` (G11), a skin
  per mini game by file name (G14, G32), a room title in data (G15); the two kits' tiles, HUDs
  and cameras clash, so each frame source keeps its own skin.
- **What is left is mostly about samples and tools.** Checking a trigger's params, a round's
  last tick and a hosted round in the game contract came with the mission contract (fixed in
  0.10); a round's own input, sounds and trigger looks wait for the first stacked sample (0.11);
  run-file start levels, traces, region edits and per-kit mutants for the creator tools (0.14).

## Format

Each gap has one entry, in the order found; ids are never reused or renumbered.

- **Id:** `G1`, `G2`, ...
- **Found:** what was found, in a sentence or two.
- **Where:** the file or module it was found in (and the one that should own it).
- **Status:** `open (0.7 Tn)` while planned for a task of this release; `fixed in 0.7 Tn (<commit>)`
  once done; or `moved to <release>` (0.10, 0.11, 0.14, 0.15, ...) with the reason.
- **Feedback:** when the owner must decide, the feedback item number (`docs/FEEDBACK-LOG.md`).
